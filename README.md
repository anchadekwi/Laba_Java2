# Formula 1 DBMS — Реляционная СУБД на Java

Учебный проект по разработке собственной реляционной системы управления базами данных на Java без использования сторонних движков БД и внешних библиотек. Предметная область по умолчанию — статистика чемпионата Формулы-1 (команды и пилоты), при этом движок универсален и позволяет создавать произвольные таблицы и связи.

Для работы с базой реализован графический интерфейс на базе **Java Swing**, который позволяет управлять данными как через прямые SQL-запросы, так и через визуальные элементы управления (конструктор таблиц, быстрые фильтры, редактирование ячеек двойным кликом, управление индексами).

## 1. Функциональные возможности

* **Операции со схемой данных (DDL):**
  * Создание новых таблиц (`CREATE TABLE`) с заданием типов столбцов, первичного ключа (`PK`) и внешних ключей (`FK`).
  * Удаление таблиц (`DROP TABLE`) с автоматической проверкой отсутствия зависимых дочерних таблиц.
  * Создание вторичных индексов по любому столбцу (`CREATE INDEX`).
* **Операции с данными (DML):**
  * Одиночная и пакетная вставка записей (`INSERT INTO ... VALUES (...), (...)`), а также вставка в выбранное подмножество столбцов.
  * Выборка данных (`SELECT`) с проекцией нужных столбцов или всех полей (`*`) и фильтрацией (`WHERE`) по операторам `=`, `!=`, `>`, `<`, `>=`, `<=`.
  * Модификация существующих записей (`UPDATE ... SET ... WHERE`).
  * Удаление записей по условию или без него (`DELETE FROM ... WHERE`).
* **Контроль целостности данных:**
  * Строгая проверка типов данных на этапе разбора запроса.
  * Контроль уникальности и непустоты (`NOT NULL`) первичного ключа (`PK`) при вставке и обновлении.
  * Контроль ссылочной целостности внешних ключей (`FK`): запрет вставки/обновления с несуществующим ключом родителя и запрет удаления/изменения родительской записи, на которую ссылаются дочерние таблицы.
* **Автоматическое сохранение и восстановление:**
  * Полная сериализация таблиц, данных и индексов в файл `f1_database.db` с использованием механизма временных файлов (`.tmp`) и резервных копий (`.bak`).

## 2. Архитектура и структура пакетов

Проект разделён на 5 независимых пакетов в соответствии с принципом единственной ответственности (Single Responsibility Principle):

```text
src/
└── f1db/
    ├── F1DatabaseApp.java          // Точка входа, инициализация стартовых данных и запуск GUI
    ├── model/                      // Слой модели данных
    │   ├── DataType.java           // Перечисление типов данных (INT, FLOAT, STRING, DATE, BOOL) и парсинг
    │   ├── Column.java             // Метаданные столбца (имя, тип, флаги PK и FK)
    │   ├── Row.java                // Одна запись таблицы (хранит значения полей)
    │   ├── TableRowIterator.java   // Итератор для безопасного последовательного обхода строк
    │   ├── Table.java              // Таблица БД: хранит схему, строки и синхронизирует индексы
    │   └── Database.java           // Корневой контейнер всех таблиц, сериализуемый на диск
    ├── index/                      // Слой индексирования
    │   └── TableIndex.java         // Вторичный индекс на базе красно-чёрного дерева (TreeMap)
    ├── storage/                    // Слой постоянного хранения и восстановления
    │   └── StorageRepository.java  // Чтение/запись БД на диск, работа с .tmp и .bak файлами
    ├── engine/                     // Слой парсинга и исполнения SQL
    │   ├── Condition.java          // Представление и проверка логического условия секции WHERE
    │   ├── QueryResult.java        // DTO-объект с результатами выполнения запроса для GUI
    │   └── SqlEngine.java          // Парсер SQL-команд, валидатор целостности и планировщик выборки
    └── ui/                         // Слой представления (Swing GUI)
        └── MainFrame.java          // Главное окно приложения и диалоги управления БД
```

## 3. Внутреннее устройство и структуры данных

### Хранение строк таблицы (`LinkedHashMap`)
Внутри класса `Table` все строки хранятся в структуре `Map<Comparable<?>, Row> rowsByPk = new LinkedHashMap<>()`, где ключом выступает значение первичного ключа (`PK`):
1. **Предсказуемый порядок обхода:** в отличие от обычного `HashMap`, `LinkedHashMap` сохраняет порядок добавления записей.
2. **Быстрый доступ по первичному ключу за $O(1)$:** проверка уникальности `PK` при `INSERT`, проверка наличия родительской записи при контроле `FK`, а также выборка вида `SELECT * FROM drivers WHERE id = 16` выполняются за константное время без перебора таблицы (план выполнения `PRIMARY KEY LOOKUP`).

### Вторичные индексы (`TreeMap`)
Для ускорения поиска по неключевым столбцам реализован класс `TableIndex`. В его основе лежит сбалансированное красно-чёрное дерево:
```java
TreeMap<Comparable, Set<Comparable<?>>> tree = new TreeMap<>();
```
* **Ключ дерева** — значение индексируемого столбца (например, количество очков `points` или `team_id`).
* **Значение** — множество `Set<Comparable<?>>` первичных ключей тех строк, у которых в данном столбце записано это значение (использование `Set` позволяет корректно индексировать столбцы с неуникальными, повторяющимися значениями).
* **Как работает поиск по индексу:**
  * Для оператора `=` вызывается `tree.get(target)` со сложностью $O(\log N)$.
  * Для диапазонных операторов (`>`, `>=`, `<`, `<=`) используются методы `tree.tailMap(...)` и `tree.headMap(...)`, которые отсекают нужную ветвь дерева за $O(\log N)$ и собирают первичные ключи подходящих записей за $O(K)$, где $K$ — число найденных элементов.
  * Полученные первичные ключи за $O(1)$ преобразуются в объекты `Row` через `rowsByPk.get(pk)`.

### Сравнение алгоритмической сложности операций в проекте

| Операция | Без вторичного индекса | С индексом (`TableIndex`) | Почему |
| :--- | :--- | :--- | :--- |
| Поиск по `PK` (`WHERE id = X`) | $O(1)$ | $O(1)$ | Прямое обращение к `rowsByPk` (`LinkedHashMap`) |
| Поиск по полю (`WHERE col = X`) | $O(N)$ (`FULL TABLE SCAN`) | $O(\log N + K)$ (`INDEX SCAN`) | Поиск узла в красно-чёрном дереве `TreeMap` |
| Поиск по диапазону (`>`, `<`, `>=`, `<=`) | $O(N)$ (`FULL TABLE SCAN`) | $O(\log N + K)$ (`INDEX SCAN`) | Навигация через `headMap` / `tailMap` в `TreeMap` |
| Вставка строки (`INSERT`) | $O(1)$ | $O(M \cdot \log N)$ | $M$ — количество активных индексов в таблице |
| Удаление строки (`DELETE` по `PK`) | $O(C)$ | $O(C + M \cdot \log N)$ | $C$ — проверка дочерних таблиц по `FK` |

## 4. Хранение на диске и защита от сбоев

За сохранение состояния отвечает класс `StorageRepository`. Все классы модели (`Database`, `Table`, `Row`, `Column`) и индексов (`TableIndex`) реализуют интерфейс `Serializable`. Это означает, что построенные индексы сохраняются прямо в файл базы данных, и при следующем запуске программы их не нужно перестраивать заново.

Чтобы база данных не повредилась при внезапном отключении питания или принудительном завершении процесса во время записи на диск, реализован двухфазный механизм сохранения:

1. **Запись во временный файл:** новое состояние объекта `Database` сериализуется через буферизованный поток `BufferedOutputStream` во временный файл `f1_database.db.tmp`. Если сбой произойдёт на этом шаге, основной файл `f1_database.db` останется нетронутым.
2. **Резервное копирование:** предыдущий рабочий файл `f1_database.db` копируется в резервный файл `f1_database.db.bak`.
3. **Атомарная подмена:** временный файл `.tmp` перемещается на место основного файла `f1_database.db` с флагом `StandardCopyOption.ATOMIC_MOVE`.

**Восстановление при запуске (`load()`):**
* Если при старте программы обнаружен остаточный файл `.tmp`, он автоматически удаляется как результат прерванной транзакции.
* Если основной файл `f1_database.db` оказывается повреждённым (ошибка десериализации), репозиторий перехватывает исключение, автоматически считывает последнюю рабочую копию из `f1_database.db.bak` и восстанавливает основной файл БД.

## 5. Поддерживаемый синтаксис SQL и типы данных

### Поддерживаемые типы данных (`DataType`)
1. `INT` — 32-битное целое число (`java.lang.Integer`), например: `1`, `44`, `-10`.
2. `FLOAT` — число с плавающей точкой двойной точности (`java.lang.Double`), например: `393.5`, `135.0`.
3. `STRING` — текстовая строка в одинарных или двойных кавычках (`java.lang.String`), например: `'Ferrari'`, `'Max Verstappen'`.
4. `DATE` — дата в формате ISO `YYYY-MM-DD` (`java.time.LocalDate`), например: `'1950-05-21'`.
5. `BOOL` — логическое значение (`java.lang.Boolean`): `TRUE` или `FALSE` (регистронезависимо).

### Примеры поддерживаемых запросов

```sql
-- 1. Создание родительской таблицы (PK — первичный ключ)
CREATE TABLE teams (id INT PK, name STRING, budget FLOAT, founded DATE, active BOOL);

-- 2. Создание дочерней таблицы со связью по внешнему ключу (FK таблица.столбец)
CREATE TABLE drivers (id INT PK, name STRING, team_id INT FK teams.id, points FLOAT, birth_date DATE, champion BOOL);

-- 3. Пакетная вставка нескольких строк
INSERT INTO teams VALUES
  (1, 'Ferrari', 135.0, '1950-05-21', TRUE),
  (2, 'Red Bull Racing', 135.0, '2005-03-06', TRUE);

-- 4. Вставка в указанные столбцы (остальные поля заполняются значением NULL)
INSERT INTO teams (id, name) VALUES (6, 'Aston Martin');

-- 5. Создание вторичного индекса по столбцу
CREATE INDEX idx_drivers_points ON drivers (points);

-- 6. Выборка всех или конкретных столбцов с условием WHERE
SELECT * FROM drivers;
SELECT name, points FROM drivers WHERE points >= 300.0;

-- 7. Обновление данных
UPDATE drivers SET points = 415.0, champion = TRUE WHERE id = 1;

-- 8. Удаление строк и таблиц
DELETE FROM teams WHERE id = 6;
DROP TABLE drivers;
```

## 6. Графический интерфейс пользователя (GUI)

Интерфейс написан на `javax.swing` (класс `MainFrame`) и разделён на четыре рабочие зоны:

1. **Левая боковая панель (Схема и таблицы):**
   * Отображает список всех таблиц БД. При клике на таблицу автоматически выполняется выборка её содержимого.
   * Кнопка **«Создать таблицу»** открывает визуальный конструктор: можно задать имя таблицы, добавить столбцы, выбрать их типы из выпадающего списка, отметить `PK` и выбрать связь `FK` с существующими таблицами без ручного написания SQL.
   * Карточка **«Структура и индексы»** выводит метаданные выбранной таблицы: количество записей, список всех полей с пометками `[PK]` и `[FK]`, а также список построенных `TreeMap`-индексов.
   * Кнопка **«Создать индекс по столбцу»** позволяет в один клик проиндексировать выбранный столбец.
2. **Верхняя панель (SQL-редактор):**
   * Многострочное поле ввода SQL-запросов с поддержкой горячей клавиши `Ctrl + Enter`.
   * Выпадающий список готовых шаблонов запросов для быстрой проверки всех функций СУБД.
3. **Центральная панель (Таблица данных и быстрые операции):**
   * Панель **«Быстрый фильтр WHERE»**: выбор столбца, оператора сравнения и значения с кнопками «Найти» и «Все строки».
   * Кнопки **«Добавить строку»**, **«Изменить ячейку»** и **«Удалить строку»**. Также поддерживается редактирование любой ячейки по **двойному клику мыши**, удаление клавишей `Delete` и контекстное меню по правому клику.
   * Любое визуальное действие (добавление, редактирование, фильтрация, удаление) автоматически формирует соответствующий SQL-запрос, выводит его в редактор сверху и пропускает через `SqlEngine`.
4. **Нижняя панель (Строка состояния и журнал событий):**
   * Выводит результат последней операции, количество найденных строк, **выбранный план выполнения** (`FULL TABLE SCAN`, `PRIMARY KEY LOOKUP` или `INDEX SCAN`) и **точное время выполнения запроса в миллисекундах**.

## 7. Применённые паттерны проектирования

1. **Iterator (`TableRowIterator`):**
   Класс `Table` реализует интерфейс `Iterable<Row>` и возвращает собственный итератор `TableRowIterator`, который создаёт снимок (`snapshot`) коллекции строк. Это позволяет безопасно обходить записи таблицы в циклах `for (Row row : table)` и избегать `ConcurrentModificationException` при модификации данных.
2. **Repository / DAO (`StorageRepository`):**
   Вся работа с файловой системой, потоками ввода-вывода и резервным копированием изолирована в отдельном классе. Ядро СУБД (`SqlEngine` и `Database`) не зависит от того, как именно данные физически записываются на диск.
3. **Interpreter / Command (`SqlEngine`, `Condition`, `QueryResult`):**
   Текстовые SQL-запросы разбираются на лексемы с учётом кавычек и скобок, преобразуются в объекты условий `Condition`, исполняются над моделью данных и возвращают унифицированный объект ответа `QueryResult`.

## 8. Запуск проекта, тестов и сборка Javadoc

### Требования
* **JDK:** версия 11, 17 или 21 (используются только стандартные пакеты `java.*` и `javax.swing.*`).
* **IDE:** IntelliJ IDEA (Community или Ultimate).

### Запуск основного приложения
1. Откройте проект в IntelliJ IDEA.
2. Запустите метод `main()` в классе `src/f1db/F1DatabaseApp.java`.
3. При первом запуске в корневой папке проекта автоматически создастся файл `f1_database.db` со стартовыми таблицами `teams` и `drivers`.
